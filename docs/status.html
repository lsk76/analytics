tg-event-analytics

Підрахунок міжетнічних інцидентів у РФ за даними Telegram — як дедуплікованих подій, а не постів. Вимоги та статус реалізації. Оновлено: 2026-06-04
готово реалізовано й перевірено в роботі частково / валідується todo ще нема

Архітектура пайплайну

collect TeleZip /Find (усі репости, unique=false), чанки по днях → Post enrich метадані каналів (TeleZip /Channels, кеш) + LLM-регіон каналу → Channel precluster content_hash + fuzzy текст (вікно) БЕЗ AI → Post.dedup_group classify LLM на ОДНОМУ представнику групи → копія на репости → is_relevant, поля dedup ковзний мікро-батч: по днях, вікно, пари — LLM-суддя → Event (стрімінг) aggregate розбивки по місяцях/регіонах/типах/категоріях тегів → ResearchRun.stats
Довідники (теги, тип конфлікту, регіон) канонізуються/закриваються — без дублів за сенсом. Дедуп-суддя бачить ОРИГІНАЛЬНИЙ текст постів, а не summary (стійкість до помилок класифікатора).

3Регіон → суб'єкт РФ; якщо невідомо — з назви/опису каналу; + населений пунктготовоRegion (85 суб'єктів, сід) + resolve_region (LLM-геолокація, закритий список); місто витягується з класифікації, summary або тексту поста; санітизація плейсхолдерів («порожньо»); fallback Channel.inferred_region
4Посилання на пости: у списку до 3, у деталях усі; в API тежготовоусюди відсортовано за к-стю підписників каналу (спадання): список (3) + «+N», деталі (усі, з 👥), API EventSerializer (топ-3 + subscribers)
