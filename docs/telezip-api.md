# TeleZip API — повний контракт (v3 + v4 Beta)

> Що саме вміє пошуковий API, які поля приймає, де його межі — і яким
> MCP-інструментом це викликати. Зібрано 2026-09-18 із трьох джерел:
> офіційний гайд («TeleZip v2», у власника), Swagger-специфікації
> (`/swagger/v3/swagger.json`, `/swagger/v4/swagger.json`) і живого
> промацування нашим ключем. Числа — станом на дату.

## 1. Доступ

```
Authorization: Bearer <TELEZIP_API_KEY>      # non-bearer припинено 2026-03-20
База v3: https://api.telezip.net/v3          # TELEZIP_BASE_URL
База v4: https://api.telezip.net/v4          # той самий хост, інший префікс
Swagger UI: https://api.telezip.net/swagger/index.html
```

Наш клієнт (`analysis/services/telezip.py`) сам розводить префікси: ендпоінт, що
починається з `/v4/`, іде повз `TELEZIP_BASE_URL`.

## 2. Ендпоінти (перевірені нашим ключем)

| ендпоінт | що робить | стан | MCP |
|----------|-----------|------|-----|
| `POST /v3/Find` | пошук, віддає ВСІ збіги одразу | ✓ (конвеєр) | `tz_ingest`, воркер collect |
| `POST /v3/FindFast` | те саме, ліміт 10 000 + `sampleOnly` | ✓ | (через v4) |
| `POST /v3/FindPaged` | посторінково | ✓ | (через v4) |
| `POST /v3/FindStats` | статистика без викачування | ✓ | (через v4) |
| `GET /v3/FindRaw` | запит у форматі бота (`text=…; days=1;`) | ✓ | `tz_probe` |
| `GET /v3/Channels` | канал за `id`/`name`/`title`/`about` | ✓ | — |
| `GET /v3/Users` | юзернейм → TelegramID | ✓ | `tz_user` |
| `GET /v3/SearchMacros` | серверні макроси `##ім'я` | ✓ | `tz_macros` |
| `GET /v3/Stats` | розмір індексу + лаг | ✓ | `tz_status` |
| `POST /v4/messages` | пошук: ліміт АБО сторінки, семпл, групування | ✓ | `tz_search`, `tz_channel_posts` |
| `POST /v4/messages/stats` | лічильники + розкладка по годинах | ✓ | `tz_stats`, `tz_calibrate` |
| `GET /v4/messages/context` | N повідомлень до/після якоря | ✓ | `tz_context` |
| `GET /v4/channels` | пошук каналів (term/title/about, сторінки) | ✓ | `tz_channels`, `tz_channel` |
| `GET /v4/users` | профілі: `userIds`/`usernames`/`userTerm`/`isBot`/`isActive` | ✓ | `tz_user` |
| `GET /v4/users/by-username` | юзернейми → id (масово) | ✓ | `tz_user` |
| `GET /v4/stats` | індекс + **глибина пошуку** | ✓ | `tz_status` |
| `GET /v4/phones`, `/v4/phones/limit` | телефон → профіль | ✗ 403: ключ без права phone lookup | — |

Бот уміє ще `/USERCHANNELS` (на які канали підписаний юзер) — в API v3/v4 його
немає (перевірено 2026-09-18).

## 3. Контракт пошуку (`/v4/messages`, `/v4/messages/stats`)

Режими (потрібен хоча б один — або фільтр по каналу/юзеру разом із `searchTerm="*"`):

| поле | що це |
|------|-------|
| `searchTerm` | пошук З ВІДМІНКАМИ: `дрон` → дрона/дрону/дронах |
| `exactTerm` | ДОСЛІВНО, без відмінків: `"сво"` не зачепить «свой» |
| `regexPattern` | патерни: картки, IBAN, телефони, крипто, координати |
| `channelTerm` | фільтр по Title/About каналу (спершу канали, потім текст у них) |

Фільтри: `channelIds[]`, `channelNames[]`, `fromUserId[]`, `fromUserName[]`,
`languages[]` (FastText-176), `requiredTags[]`/`excludedTags[]` (exclude лише
разом із required), `hasMedia`, `unique` (згортає репости), `source`
(`TeleZip` — телеграм, дефолт; `DarkZip` — зливи баз; `All`), `topMessageId`
(одна гілка коментарів), `fromDate`/`toDate` (треба хоча б одну).

Вивід: `limit` (+`sampleOnly` — випадкова вибірка) **АБО** `pageSize`+`pageToken`
— взаємовиключні; `groupByChannel` сортує по каналу.

Оператори всередині `searchTerm`/`exactTerm`/`channelTerm`: пробіл = АБО,
`+` = І, `-слово` = НЕ (злитно), `( … )`, `слово*` (префікс), `"фраза"`,
`"a b"~N` (відстань). Робоча форма: `ТЕМА +(ДІЯ) -(ШУМ)`.

## 4. Межі («відлуп»)

* пошук довше **3 хв**; збіг понад **300 000** повідомлень; понад **10 000** каналів;
* `channelTerm`, що зачепив понад **20 000** каналів;
* **глибина індексу** — `GET /v4/stats` → `searchDateLimit`:
  2026-09-18 це `minSearchDate 2025-10-01`, `maxDaysBack 352`.
  **Старіше не шукається взагалі** — не помилка, а порожня відповідь. Вікно
  повзе: те, що зібрано торік, перезібрати вже НЕ вийде (ще один аргумент
  тримати сирі пости в БД, а не перезбирати з нуля).
* лаг індексації (`delaySeconds`) — 2026-09-18 близько 35-40 с, тобто «зараз»
  реально доступне майже наживо.

## 5. Граблі, знайдені промацуванням

* **404 ≠ «нема ендпоінта».** `/v4/users?usernames=X` віддає 404, коли профілю
  просто немає; `/v4/users?userTerm=X` на те саме — 200 із 822 збігами.
  Тому довідники трактують 404 як «порожньо» (`_run_soft`).
* **`anchorDate` у `/v4/messages/context` обов'язкова** (без неї 400
  `INVALID_ANCHOR`) і має бути БІЛЯ дати повідомлення: сусідній день
  прощається, далекий → 404 `ANCHOR_NOT_FOUND`. Дату беруть із хіта пошуку.
* **Фільтр по каналу/юзеру без тексту API не приймає** — треба `searchTerm="*"`.
  Інструменти підставляють його самі.
* **4xx не варто ретраїти** — клієнт раніше повторював будь-яку помилку 5 разів
  (15 с і 5 зайвих викликів на кожну помилку валідації). Тепер 4xx (крім 429)
  падає одразу.
* **Негація `-(…)` на широкому вікні** — 500/timeout/429, ~68× повільніше;
  краще позитивний `+(…)`, а сміття відсіює класифікатор.
* **`unique=true` занижує охоплення** (репости — це теж охоплення); для метрики
  «скільки людей» бери `unique=false` і рахуй distinct авторів.
* Макроси (`GET /SearchMacros`) — готові підзапити виду
  `##вч_93498` → `"93498 частина"~2 | "в/ч 93498" | …`; вставляються прямо в `query`.

## 6. Що з цього вживає конвеєр

Збір задач (`collect`/`mon_collect`) ходить ТІЛЬКИ у `POST /v3/Find` — перевірений
шлях із чанками, ретраями й глобальним семафором (`TelezipSlot`). Решта контракту
доступна операторові через MCP-інструменти групи `telezip` (див.
`docs/mcp-server.md`), які нічого не пишуть у БД, крім явного `tz_ingest`.

Типовий маршрут: `tz_stats` (скільки цього є) → `tz_calibrate` (дублі й ризик
відлупу) → `tz_search` (подивитись тексти) → `task_update` (зафіксувати запит у
задачі) → `run_create` (плановий збір чанками).
