# Economic-tension events pipeline (E1–E4)

**Канон** конвеєра детекції **економічних подій** по 8 нацреспубліках РФ за 2026 рік.
Це конвеєр **подій-репортажів** (як `docs/ethnic-events-pipeline.md`), а **не коментарів**
(`docs/comments-analysis-pipeline.md`). Заповнює 4 колонки таблиці етнічної напруги:

| Код | Колонка таблиці | Тег |
|-----|-----------------|-----|
| **E1** | повідомлення про економічні суперечки між регіоном і федеральним урядом (субсидії, квоти, ресурси) | `econ_event` 2366 `екон_суперечки_регіон_центр` |
| **E2** | висвітлення **унікальних корупційних ЕКОНОМІЧНИХ** скандалів у республіці | `econ_event` 2367 `корупційні_скандали` |
| **E3** | протестна активність та економічні страйки | `econ_event` 2368 `протести_економічні_страйки` |
| **E4** | заяви місцевої адміністрації про економічну дискримінацію республіки центром | `econ_event` 2369 `влада_про_екон_дискримінацію` |

Результат — `Event` у **task=6** (`ethnic-tension-events`), `review_status=approved`,
`region_subject` = республіка, з прив'язаними `Post` (джерела). Метрика в комірці —
**два числа: «всього 2026 / лише квітень-травень»**.

---

## Потік (5 кроків + 2 аудити)

```
0. теги+TagCategory  → econ_event (2366-2369)  [ОБОВ'ЯЗКОВО створити РЯДОК TagCategory, не лише Tag.category]
1. збір   collect_econ_multi.py   → '*' unique по локальних каналах, кеш econ_raw_<key>.json
2. фільтр (у тому ж скрипті)      → AND-логіка keyword по 4 категоріях → econ_<key>_candidates.json
3. класифікація  Workflow         → Sonnet, гео=республіка + справжня подія типу → econ_<key>_confirmed.json
4. групування+аудит  Workflow     → дедуп дублів в інциденти + скептична перевірка → econ_incidents.json
5. створення  create_econ_events.py → Event(task=6, tag, posts), approved
6. суворий ре-аудит  Workflow      → звірка з ТОЧНИМ формулюванням колонки (misfit/old/uncertain)
7. economic-purity пас  Workflow   → для E2: лишити ЛИШЕ чисто фінансову корупцію
```

Кроки 3,4,6,7 — оркестровані Claude Code через `Workflow` (агенти Sonnet), не docker-воркери.

**Запит:** `find_posts_range("*", a, b, [], unique=True, channel_ids=[c.tg_id])` по каналу × місяцю
(1-6.2026). `*` без негації — швидко (див. memory `telezip-negation-slow`). Усі сирі пости (`t`≥40
символів) кешуються в `econ_raw_<key>.json` (текст до 1500 символів) — **щоб майбутні колонки
фільтрувати офлайн БЕЗ повторного TeleZip**.

**AND-логіка ключових слів** (re.I). Кандидат типу = (тема ∧ дія). Реальні регекси:

```python
# E1 — економічна суперечка регіон ↔ федеральний центр  (ТЕМА ∧ СПІР)
E1_TOPIC = r"(субсиди|дотаци|межбюджетн|трансферт|\bквот|недофинансир|дефицит\w*\s+бюджет|госдолг|распределени\w*\s+(средств|денег|финанс)|\bнедра\b|нефтегаз|бюджетн\w*\s+обеспеченност|выравниван|отчислени\w*\s+в\s+(центр|москв|федеральн)|налог\w*\s+(в|уход\w*\s+в)\s+(центр|москв|федеральн)|федеральн\w*\s+бюджет)"
E1_DISPUTE = r"(спор|претензи|несправедлив|центр\s+забира|москва\s+забира|забира\w*\s+(деньги|средств|налог)|требова\w*\s+(от|у)\s+(центр|москв|федеральн)|недовольств\w*\s+(центр|москв|федеральн)|обдел|недополуча|должн\w*\s+возвраща|регион\w*\s+(против|обижен)|центр\s+не\s+да)"

# E2 — корупційний скандал  (ТЕМА ∧ ДІЯ)
E2_TOPIC  = r"(коррупц|взятк|\bоткат\w*|хищени|растрат|казнокрад|нецелев\w*\s+расход|госзакуп|злоупотреблени\w*\s+(должностн|полномочи)|превышени\w*\s+должностн|мошенничеств)"
E2_ACTION = r"(задержа|аресто|обыск|уголовн\w*\s+дел|возбуд\w*\s+(уголовн|дел)|приговор|осужд|посади\w*\s+на\s+срок|отставк|следстви|фигурант|следственн\w*\s+комитет|\bСКР\b|взят\w*\s+под\s+стражу|объявлен\w*\s+в\s+розыск)"

# E3 — протест / економічний страйк  (ТЕМА ∧ ДІЯ)
E3_TOPIC  = r"(протест|митинг|пикет|забастовк|\bстрайк|голодовк|обманут\w*\s+дольщик|невыпла\w*\s+зарплат|задолженност\w*\s+по\s+зарплат|массов\w*\s+увольнени|сокращени\w*\s+(рабоч|персонал|штат)|перекры\w*\s+(дорог|трасс|улиц|движени)|акци\w*\s+протест|трудов\w*\s+(спор|конфликт)|профсоюз)"
E3_ACTION = r"(вышл\w*\s+на|провел|устро|объяв|потребова|перекры|собрал|организова|начал\w*\s+(забастовк|голодовк)|выйти\s+на\s+улиц|пожалов|записа\w*\s+(видео)?обращени)"

# E4 — заява місцевої влади про економічну дискримінацію  (МОВЕЦЬ ∧ СКАРГА)
E4_SPEAKER = r"(глава\s+республик|глава\s+рег|губернатор|президент\s+республик|министр|премьер|вице-?премьер|правительств\w*\s+(республик|рт|рб|ри|чр|рд)|госсовет|депутат\w*\s+(госсовет|думы|парламент)|спикер)"
E4_GRIEV   = r"(несправедлив\w*\s+(финансир|распределени|бюджет|отношени)|недофинансир|обдел|мало\s+(получа|выделя)|больше\s+отчисля|должн\w*\s+(возвраща|оставля)|дискриминац\w*\s+(в\s+финансир|бюджет|экономи|отношени)|регион\w*\s+(обдел|обижен)|центр\s+забира)"
```

```python
def match_types(t):
    ty=[]
    if E1_TOPIC.search(t) and E1_DISPUTE.search(t): ty.append("E1")
    if E2_TOPIC.search(t) and E2_ACTION.search(t):  ty.append("E2")
    if E3_TOPIC.search(t) and E3_ACTION.search(t):  ty.append("E3")
    if E4_SPEAKER.search(t) and E4_GRIEV.search(t): ty.append("E4")
    return ty
```

> Keyword — це лише **грубий відсів кандидатів** (крок «1 Keyword 2 класифікація», узгоджено з
> замовником саме для подій). Точність дає LLM-класифікація+аудит нижче. E2 (корупція) дає
> найбільше кандидатів скрізь; E1/E4 — найменше.

Кожен агент читає зріз `econ_<key>_candidates.json`, повертає `{confirmed:[{i,types,summary}]}`.

**Промпт** (`prompt(key, region, a, b)`):

```
Ти — аналітик соціально-економічної напруги в нацреспубліці РФ <region>. Класифікуй
кандидати-пости з місцевих каналів республіки.

КРОК 1. Прочитай econ_<key>_candidates.json. Візьми ЛИШЕ елементи з глобальними індексами
a…b включно. Поле "t" = оригінальний текст, "ch" = канал, "date" = дата.

КРОК 2. Для кожного поста виріши, чи це СПРАВЖНЯ подія потрібного типу, що сталася В <region>
(або прямо стосується республіки). Типи:
- E1 — економічна суперечка регіон ↔ федеральний центр: конфлікт/претензія республіки до
  Москви щодо субсидій, дотацій, квот, ресурсів, міжбюджетних відносин, недофінансування

ПРАВИЛА ВІДСІВУ: подія не в <region> → відкинь (гео); реклама/гороскоп/погода/спорт/
```

## Крок 4 — групування дублів + адверсаріальний аудит (Workflow `group-audit-econ-8rep`)

Один скептичний агент на республіку. Зливає повідомлення про **ту саму подію** (той самий
арешт/вирок/скандал) в ОДИН інцидент і ще раз перевіряє. Повертає
`{incidents:[{member_indices,types,label,valid,reason}]}`.

**Промпт** (`prompt(key, region)`):

```
Ти — СКЕПТИЧНИЙ аудитор соціально-економічних подій у республіці <region>.
ВХІД: econ_<key>_confirmed.json {i,types,summary} + econ_<key>_candidates.json (i→"t" повний текст).

1. КЛАСТЕРИЗАЦІЯ (головне). Згрупуй записи про ОДНУ Й ТУ САМУ реальну подію в один інцидент
   (різні канали/дати/формулювання). Напр. «затримали ексміністра Сулейманова» +
   «Сулейманова заарештували в аеропорту» = один інцидент. Об'єднай i в member_indices.
   Різні справи/особи — окремі інциденти.
2. АДВЕРСАРІАЛЬНА ПЕРЕВІРКА. Прочитай повний текст "t":
   - Гео: подія в <region>? Інакше valid=false.
   - Тип: E2 — саме КОРУПЦІЯ посадовця/держструктури, не побутовий кримінал; E1 — конфлікт
     республіки з центром за гроші/ресурси; E3 — реальний протест/страйк/трудовий конфлікт;
     E4 — заява влади республіки про економічну дискримінацію центром.
3. ВЕРДИКТ: member_indices, types (фінальні), label (укр, стисло), valid, reason. Поверни і
   valid, і invalid.
```

## Крок 6 — суворий ре-аудит на відповідність колонці (Workflow `strict-reaudit-econ`)

Звіряє кожну подію з ТОЧНИМ формулюванням заголовка колонки. Вердикт **fit / misfit / old /
uncertain**. Ключове правило «**старі події**»: ретроспектива давнього злочину БЕЗ свіжої
процесуальної дії 2025-2026 → `old`; але затримання/обшук/вирок/апеляція/конфіскація 2026 =
актуально (`fit`), навіть якщо сам злочин давній. `misfit`/`old` → `review_status="rejected"`;
`uncertain` → даємо замовнику посилання `…/admin/analysis/event/<id>/change/` на рішення.

## Крок 7 — economic-purity для E2 (Workflow `e2-economic-purity`)

Колонка E2 = «корупційні **ЕКОНОМІЧНІ** скандали». Лишаємо лише фінансове ядро.

**Промпт** (`prompt(a, b)`), вердикт **economic / non_economic / uncertain**:

```
Колонка E2 = «висвітлення унікальних корупційних ЕКОНОМІЧНИХ скандалів у республіці».
Залиш лише ЧИСТО ЕКОНОМІЧНУ корупцію.
- economic (ЗАЛИШИТИ): розкрадання/привласнення/розтрата бюджету; шахрайство з бюджетом,
  субсидіями, держконтрактами/держзакупівлями; хабар (гроші/майно)/відкат; незаконне
  збагачення, конфіскація корупційних активів; махінації із землею/держмайном; перевищення
  повноважень з МАЙНОВИМ/бюджетним збитком; нецільові витрати; фіктивне працевлаштування.
- non_economic (ВІДХИЛИТИ): зловживання/перевищення БЕЗ фінансово-майнового ядра —
  фальсифікація доказів, незаконне затримання, катування/насильство/смерть, приховування
  ДТП, службовий підлог без вигоди, суто процесуальні порушення, покровительство без грошей.
- uncertain: хабар присутній, але домінує насильницький/процесуальний сюжет, або сума не
  вказана.
ВАЖЛИВО: хабар=гроші=economic; земельні/майнові схеми=economic; збиток бюджету=economic.
```

`non_economic` → reject; `uncertain` → замовнику на рішення (за вказівкою «відхили межові» —
теж reject).

## Уроки / граблі

1. **E1/E4 майже скрізь = 0, окрім Саха — це РЕАЛЬНО, не пропуск даних.** Той самий keyword-
   фільтр дав Саха **247** E1-кандидатів проти 4-33 в інших; а не-Саха кандидати — це
   федеральні гроші, що ТЕЧУТЬ у республіку (співпраця), реклама, репости Путіна, не суперечки.
   Причини: (а) у Саха вільні розслідувальні канали (`real_yakutia`, `pryanayayakutia`), решта
   — офіційні/кримхроніка; (б) арктична залежність (північний завіз, авіасубсидії, вугілля).
   Фед-економічна напруга в ІНШИХ республіках живе **в коментарях-критиці** (Татарстан 18%),
   а не в подіях-репортажах. Подія E1 ловиться лише там, де вільне медіа + реальний привід.
2. **E2 ≠ будь-яка корупція**: тільки чисто економічна (крок 7). Насильство/фальсифікація/
   незаконне затримання — НЕ E2.
3. **Дедуп критичний**: один скандал (Сулейманов, Мурзагулов-подібні) репортять 5-13 каналів;
   без групування E2 завищується в рази. 1051 confirmed → ~356 інцидентів.
4. **Чечня = 0 скрізь** — повний інфо-контроль локальних каналів (як і в етнічному конвеєрі).
5. **TagCategory обов'язковий** (крок 0) — інакше адмінка-фасет ламається на `?e=1`.
6. **Post unique(task,url)** — econ-подія пропускає URL, уже зайнятий ethnic-подією.
7. **Кеш `econ_raw_<key>.json`** (~152k сирих постів) — нові колонки рахувати з нього, без
   повторного TeleZip. /etc/hosts фікс telezip переставляти перед збором (memory `vpn-dns-hosts-fix`).
8. **Завжди перевіряй виконання** фонових збору/воркфлоу одразу (memory `verify-jobs-execute`).
